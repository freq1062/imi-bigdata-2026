# GNNExplainer-Based Explainability Setup Guide

This document explains how to set up and run the new GNNExplainer-based cluster interpretation pipeline, including local Ollama LLM integration.

---

## Overview

The new explainability notebook replaces the RF/SHAP approach with a four-phase GNNExplainer pipeline:

1. **Phase 1: Representative Sampling (Medoids)**
   - Uses `GaussianMixture.predict_proba()` to find the most representative nodes per component
   - Prioritizes known fraud anchors if they're in the cluster
   - Samples top-5 nodes per component

2. **Phase 2: Explanation Generation**
   - Runs PyTorch Geometric's GNNExplainer on each medoid
   - Extracts edge masks (0-1 importance per edge) and feature masks (0-1 importance per feature)
   - Works with your existing DGI model architecture

3. **Phase 3: Cluster Profile Synthesis**
   - Aggregates explanations across the 5 medoids
   - Identifies common features, structural motifs (star/chain/clique), and transaction patterns
   - Computes statistics: avg amount, merchant categories, time patterns

4. **Phase 4: LLM Interpretation**
   - Sends structured cluster profiles to local Ollama
   - Gets domain-expert interpretation of cluster semantics
   - Falls back to template prompts if Ollama unavailable

## Prerequisites

### Python Packages

The notebook requires these additional packages beyond your current environment:

```bash
pip install torch-geometric requests
```

Verify your existing packages include:
- `torch`, `torch_geometric` (for GNNExplainer)
- `scikit-learn` (for GaussianMixture)
- `pandas`, `numpy`
- `matplotlib`, `seaborn` (for visualizations)

### Artifact Files

The notebook expects these files (generated by your training pipeline):

- `dgi_model.pt` - Trained DGI model checkpoint
- `dgi_embeddings.pt` - Pre-computed customer embeddings (61410 × 64)
- `dgi_gmm.joblib` - Fitted GaussianMixture model
- `dgi_component_assignments.csv` - Component membership for each customer
- `data_graph.pt` - Heterogeneous graph data structure
- `transactions_with_features.csv` - Transaction-level data for context

If any are missing, the notebook will error at the "Load Pre-Trained Artifacts" phase.

## Setting Up Ollama (Local LLM)

### Option 1: Docker (Recommended)

If you have Docker installed:

```bash
# Pull and run Ollama container
docker run -d --name ollama -p 11434:11434 ollama/ollama

# Verify running
curl http://localhost:11434/api/tags
```

### Option 2: Direct Installation

Download and install from [ollama.com](https://ollama.com):

```bash
# On Linux
curl https://ollama.ai/install.sh | sh

# Start Ollama daemon
ollama serve
```

The server will run on `http://localhost:11434` by default.

### Option 3: Remote Server

If running on a different machine:

1. Ensure Ollama is accessible (check firewall, port 11434)
2. Update `OLLAMA_ENDPOINT` in the notebook:
   ```python
   OLLAMA_ENDPOINT = "http://your-server-ip:11434"
   ```

## Troubleshooting

### "Cannot connect to Ollama"

**Problem**: `✗ Cannot connect to Ollama at http://localhost:11434`

**Solutions**:
1. Ensure Ollama server is running: `ollama serve`
2. Check port 11434 is open: `netstat -tuln | grep 11434`
3. Try direct test: `curl http://localhost:11434/api/tags`
4. If remote, verify IP/firewall settings

### "GNNExplainer failed for node X"

**Problem**: Individual GNNExplainer runs fail

**Solutions**:
1. This is non-fatal; the notebook skips failed nodes (expected for ~5-10%)
2. Usually due to graph connectivity issues for isolated nodes
3. Increase `num_epochs` in `run_gnnexplainer_on_node()` if timeout

### "Missing artifact file"

**Problem**: `FileNotFoundError: dgi_model.pt`

**Solutions**:
1. Verify training pipeline produced all outputs
2. Update file paths in "Load Pre-Trained Artifacts" cell
3. Check artifact names match your training script

### "Insufficient memory for Phase 2"

**Problem**: GNNExplainer runs fail with OOM error

**Solutions**:
1. Reduce number of components to process:
   ```python
   # Sample only first 10 components
   medoids_by_component = {k: v for k, v in medoids_by_component.items() if k < 10}
   ```
2. Reduce `num_epochs` in `run_gnnexplainer_on_node()` (e.g., 50 instead of 100)
3. Use smaller batch sizes or GPU with more memory

## Customization

### Adjust Medoid Count

Change number of nodes sampled per component:

```python
medoids_by_component = sample_component_medoids(
    gmm_model,
    all_customer_embeddings,
    component_df,
    n_samples=10,  # Instead of 5
    anchor_fraud_ids=anchor_fraud_ids
)
```

### Adjust Feature Threshold

Change sensitivity of feature importance thresholding in Phase 3:

```python
# In aggregate_component_profile(), line:
critical_f, _ = threshold_masks(feature_mask=exp['feature_mask'], top_k=0.1)  # Top 10% instead of 20%
```

### Use Different LLM Model

Change which model Ollama uses:

```python
OLLAMA_MODEL = "neural-chat"  # Faster
# or
OLLAMA_MODEL = "orca"  # Higher quality
# or
OLLAMA_MODEL = "llama2"  # Official Llama 2
```

### Adjust LLM Temperature

Control LLM creativity (lower = more deterministic):

```python
interpretation = query_ollama(prompt, temperature=0.1)  # More deterministic
```

## Integration with Streamlit App

The cluster interpretations can be displayed in your `Home.py` Streamlit app:

```python
import pandas as pd

# Load narratives
narratives_df = pd.read_csv('gnnexplainer_cluster_narratives.csv')

st.header("🧠 Cluster Interpretations (GNNExplainer)")
for idx, row in narratives_df.iterrows():
    with st.expander(f"Cluster {int(row['component_id'])} - {row['features']}"):
        st.write(f"**Motif:** {row['dominant_motif']}")
        st.write(f"**Avg Amount:** ${row['avg_amount']:.2f}")
        st.markdown(row['interpretation'])
```
